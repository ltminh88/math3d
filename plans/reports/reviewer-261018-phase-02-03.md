# Review: phase 02 (engine/input/audio/UI kit/bench) + phase 03 (learning + store)
Scope: src/core/**, src/ui/kit/**, src/dev/**, bench.html, src/learning/**, src/store/**. CI already green; below = defects CI misses. Each claim verified against the code.

## Critical
C1. **Overlay eats every canvas pointer.** `#ui > * { pointer-events: auto }` (src/styles/base-reset.css:57) has specificity 1-0-0 and beats `.kit-layer {pointer-events:none}` (src/ui/kit/styles/ui-kit.css:1-5) and `.kit-fade {pointer-events:none}` (ui-kit.css:146-152). Both are full-screen direct children of #ui (engine.ts:84 fade, :94 scene layer) → the canvas never receives pointerdown, so drag and tap-select are dead in bench and app. Fix: `#ui > .kit-layer, #ui > .kit-fade:not(.kit-fade--on) { pointer-events: none }`, or write the base rule as `:where(#ui) > *`.
C2. **Audio + speech never unlock on iPad.** `bindUnlock` listens for `pointerdown` and drops the listener after the first call, whether or not it worked (core/audio/audio-engine.ts:59-68; speech unlock rides the same handler, engine.ts:81). Under HTML user-activation rules, a touch `pointerdown` does not trigger activation (only `pointerup`/`touchend`/`click`/`keydown` do), so `resume()` and `speak()` run without activation on the gate device and are never retried. iOS also moves a running context to suspended/'interrupted' after lock or backgrounding, and `play()` bails when state isn't running (:94) → no sound for the rest of the session. Fix: listen on `pointerup`/`touchend`/`click`/`keydown`, remove the listener only once `ctx.state === 'running'`, and keep a gesture listener that resumes whenever the state isn't running.
C3. **Keyboard trap + Enter collision (WCAG 2.1.2 / 2.5.7).** InteractionController handles `Tab` on `document` even while a DOM button has focus (it only skips Enter/Space on BUTTON) and wraps around forever (core/input/interaction-controller.ts:59-61, tap-select-controller.ts:57-69). Once a scene registers pickables, Tab can't reach the number pad, choice buttons or menus. Its keydown listener is registered before the pad's and swallows `Enter`, so the pad's Enter-to-submit never fires (ui/kit/number-pad.ts:90-98; you can see it in the bench). Fix: cycle 3D targets with arrow keys only (or release Tab at the end of the list), ignore keys whose target is inside #ui controls, and have the pad handle keys only while it has focus.

## Warning
W1. **Leitner demotes once per wrong attempt.** session-recorder.ts:52-78 calls `applyAttempt(correct:false)` for every wrong answer: 2 wrong then correct → box-2, revealed after 3 wrong → box-3 (box 5 drops to 2 in one question). The spec says wrong → box-1. Fix: count every attempt, but apply one box transition per question.
W2. **Schema upgrade can hang boot forever.** `openGameDb` has no `blocked`/`blocking`/`terminated` handlers (store/idb-database.ts:22-34). The doc comment says it "rejects when blocked", but idb leaves the promise pending. When v2 ships, any other open tab or old PWA window blocks the open indefinitely, and with no `blocking` handler that window never closes its connection. Fix: `blocking: () => db.close()` plus a reload prompt; `blocked`: reject after a timeout; `terminated`: reopen.
W3. **Spec gap: no fallback when IndexedDB is unavailable** (phase-03 risk table: "in-memory fallback + toast"). `openGameStore` just rejects (game-store.ts:70), so phase 04 boot would crash in a blocked-IDB browser. Fix: an in-memory GameStore implementation, or explicitly defer it to 04.
W4. **Pointer stream can get stuck.** PointerInput never handles `lostpointercapture`. If capture fails (swallowed at pointer-input.ts:60-64) or is lost without up/cancel (element removed, iOS system gesture), `activeId` never clears and every later pointerdown is ignored (:57,:76). `interaction.reset()` doesn't clear it either. Fix: treat `lostpointercapture` as cancel and add `PointerInput.reset()`, called from onBeforeInit.
W5. **Two sources of truth for device settings.** AudioEngine keeps mute/volume in `nsq.audio` with default 0.7 (core/audio/audio-settings.ts:17-18); settings-store keeps `sound`/`volume` in `nsq.settings` with default 0.8. The quality tier lives both in `nsq.qualityTier` and in `settings.qualityTier`. The fade honors only the OS media query, not `settings.reducedMotion` (ui/kit/fade-transition.ts:5). Spec: "mute persisted via settings". Fix: back AudioSettingsStore and the quality tier with SettingsStore.
W6. **The whole overlay is a live region.** `<div id="ui" aria-live="polite">` (index.html:16, bench.html) makes screen readers announce every UI mutation (pad, layers, bench HUD twice a second) and duplicates `announce()`. The announcer creates its region lazily at the first call (ui/kit/aria-announcer.ts:3-19), and VoiceOver often drops that first message. Fix: remove aria-live from #ui and create the announcer region at boot.
W7. **Outbox retry isn't idempotent.** A duplicate batchId fails `outbox.add` with ConstraintError (progress-repository.ts:115). If `refresh()` throws after a durable commit (game-store.ts:126/159), the caller sees a failure, a retry throws ConstraintError, and `session-committed` never fires, so the phase 09 flush is never triggered. Fix: treat ConstraintError on byBatchId as already committed, and notify commit listeners even when refresh fails.
W8. **Perf gate can measure mixed tiers.** AdaptiveQuality stays on in the bench (engine.ts:119-127) and can step down mid-run, persisting the lower tier. The 60 s report records only the final tier (dev/perf-bench-hud.ts summaryWithInfo). Fix: add an engine option to disable adaptive quality in the bench, or log every tier change in the run report.

## Suggestion
S1. Square facts get equal-value wrong options. For 3x3, the wrong options can be "3 x 4" and "4 x 3" (expression-choice.ts:14-26), the commutative pair the plan wants kept out of the same question. Dedupe wrong options by value.
S2. `sessionNo` comes from the in-memory snapshot (game-store.ts:117). Two tabs write the same counter. Read `meta` inside the transaction instead.
S3. `engine.dispose()` doesn't tear down the live scene or close the AudioContext/music interval (engine.ts:181-194; AudioEngine has no dispose). iOS caps the number of AudioContexts.
S4. Music keeps scheduling while the tab is hidden (music-loop.ts:35); only rendering pauses. Suspend the context on visibilitychange.
S5. settings-store: corrupt JSON sets `persistent=false` permanently even though later writes succeed (settings-store.ts:70), so the user gets a false "won't be saved" warning. Reset the flag after the first successful setItem.
S6. Planner: the box-5 interval of 16 is unused (mastered facts are drawn every session, oldest first), and repeated facts in short pools can land next to each other (session-planner.ts:71,103-109).
S7. `projectToGround` allocates a new Plane on every pointermove (raycast-picker.ts:53). Keyboard focus on 3D items emits `focus` but is never announced. Wire it to `announce()`.
S8. Note on MIGRATIONS (save-migrations.ts:31): steps must never await non-IDB promises, or the versionchange transaction auto-commits.
